### 2.1 与圆锥曲线课件的同与不同

| 层 | 圆锥曲线（既有） | 立体几何（本次） | 说明 |
| --- | --- | --- | --- |
| ① 内容层 | `bento/slides` 文档模型 | **同** | 完全复用 |
| ② 渲染层 | Bento 单文件壳 | **同（换壳内容）** | 壳 = 除 `bento-doc` 块外的全部，已实测比对 |
| ③ **数学/几何层** | `packages/math`：`plotImplicit` marching squares | **自建 3D 投影 + 截面求交** | ← **唯一的结构性差异** |

### 2.2 关键设计决策

| 决策 | 原因/依据 |
| --- | --- |
| **不复用 `packages/math` 的曲线引擎** | `plotImplicit` 解决的是**隐式曲线** `F(x,y)=0`（椭圆/双曲线/抛物线）。多面体不是隐式曲线，套用不上——硬套只会把问题复杂化 |
| **正方体用斜二测，不用轴测** | 第一版用「x 向右下、y 向左上」的轴测，`A₁` 投影落在 `ABCD` **内部**，立方体被压成扁平菱形。斜二测把前面画成正方形、深度向右上偏移 45°，上底面才「盖在」下底面之上 |
| **截面顶点用求交，不硬编码** | `BM>2/3` 时截面是五边形，多出的顶点由「平面 × 棱」解出。硬编码四边形顶点无法覆盖临界后的形态 |
| **动效全用 SMIL，不用 JS 补间** | 与既有两份课件一致；控制条靠 `setCurrentTime` 强写时间轴，若用 JS 补间则控制条的暂停/定位全部失效 |
| **复用 `conic-exams` 的壳** | 壳里的 `bento-rt` 是 base64 压缩运行时（二进制），**无法重新生成**；而 `--embed` 只替换 `bento-doc` 块，壳原样保留。实测两壳差异仅为控制条前的空行数 |
| **加 `assertContentSafe()` 自检** | 「裸露的 `<` 被 HTML 吞掉」这个坑在真题精讲与本课件上**各踩了一次**，必须前置拦截 |
| **像素差分器重写为纯 Node** | 原验证用 PowerShell + System.Drawing（仅 Windows）。新差分器自解码 PNG，跨平台且无需 .NET |

## 3. 实现流程（本次实际操作步骤）

12 步，分四个阶段。**其中 5 步是「发现问题 → 回修」的闭环**——这才是流程的主体，而不是一次写对。

### 阶段 A · 准备（2 步）

1. **核实壳复用可行性**
   比对 `conic-moving-point` 与 `conic-exams`：抽出各自的「壳 = 全文去掉 `bento-doc` 块」，
   实测两壳 694,121 / 694,133 字符，差异仅在控制条前的空行 → 确认可安全复用。
2. **起验证环境**
   `chrome --remote-debugging-port=9222 --user-data-dir=<临时目录> --headless=new`
   （用临时 profile，避免像早先那样在工程目录里堆出 `.edge_*` 缓存）。

### 阶段 B · 生成（3 步）

3. **复核解题推导**
   两道题的每一步与用户提供的原卷解析逐式对齐（题1 → `(0, 2/3]` 选 D；题2 → `PF/BF = 1/2 或 2`）。
   推导不过关，图形和动画都无从谈起。
4. **编写 `tools/build-solid.mjs`**
   自下而上搭：画板工厂 → 3D 线性代数 → SVG 片段工厂 → 正方体投影与截面求交 →
   四棱锥投影 → 页面装配（`stepCards`/`figSlide`）→ 9 页内容。
5. **首次构建 → 语法错误**
   中文字符串里混入 3 处 **ASCII 双引号**（`"平行"`），JS 解析失败。
   ⚠️ 危险之处在于：`--embed` 因语法错误**没有执行**，但后续命令照跑，
   于是成品里留着从 `conic-exams` 复制来的**旧文档（17 页）**，从文件名和体积看毫无异常。
   靠随后 `check-doc` 打出 `slides: 17 | title: 圆锥曲线与立体几何…` 才暴露——
   **这就是为什么每次 embed 后必须立刻 check-doc**。

### 阶段 C · 构建与验证（4 步）

6. **创建成品**
   `Copy-Item conic-exams.bento.html solid-geometry.bento.html`（拿壳）→ `--embed`（换 doc）
   → `inject-controller.mjs`（注入控制条）。得到 9 页 / 755 KB（该步中间态）。
7. **拍屏 → 404**
   `shoot-deck.mjs` 传了相对路径，拼出 `file:///solid-geometry.bento.html` → `ERR_FILE_NOT_FOUND`。
   排查靠临时写的 `diag-solid.mjs`（读 `window.bento` / `document.title` / 控制台日志），
   确认传**绝对路径**后 boot 正常（`docSlides: 9`）。
8. **双帧截图 + 像素差分**
   9 页 × a/b 两帧，`pixdiff.mjs` 逐像素比对：
   S2=778 / S3=780 / S8=380 在动，其余 6 页静态符合设计。
9. **差分器可信度对照**
   用同一脚本回跑既有 `shots/svg`，**复现出文档 §7.1 记录的原值**
   （S1=176、S6/7=848/847、S10=683、S11/12=0、S13=211）→ 证明测量方法可靠，不是自说自话。

### 阶段 D · 缺陷回修（3 个缺陷）

10. **缺陷 1 · 正方体投影错误**（目视发现）
    截图里 `A₁` 落在 `ABCD` 内部，立方体读作扁平菱形。
    → 换斜二测投影（`CU_KX/CU_KY`），同步调整 8 个顶点标签偏移与坐标轴标注位置。
11. **缺陷 2 · 文字被 HTML 吞掉**（目视发现）
    S8 第④张卡显示原始 `\frac{PF}{BF}=...`。
    排查：内容里的 `$0<k<1$`，**`<k<1` 被 HTML 解析器当成标签开头**，吞掉了后续文字。
    → 改写为 `&lt;`，并新增 `assertContentSafe(doc)`：生成前扫描所有 text 元素，
      命中即抛错并打印 `slide / element` 定位。
    → 补做**正反测试**：干净内容通过、注入裸 `<` 被拦下（exit 1）。
    → 修 guard 的误报：`< BM`（后跟空格）与 `<1`（后跟数字）在 HTML5 里是安全字面量，
      正则须为 `/<[A-Za-z/!?]/` 而非 `/<[^>]/`。
12. **缺陷 3 · 排版溢出 10 处**（`validate()` 发现）
    `window.bento.validate()` 报 10 处 text-overflow（文字超出卡片、会压到下一张卡）。
    根因：`stepCards()` 最初**等高**分配右栏，而各卡文字量差 2~4 行。
    → 改为**按权重分配高度**（`h = 可用空间 × w / Σw`，末张吃掉取整余量）。
    → **弯路**：凭直觉把最大权重给了 S8 第②张（EF 分量式），validate 仍报②溢出 20px——
      真正超高的是第③张（线面角方程）。改成**先读 validate 报出的实际需求像素、再据此设权重**，
      才拿到 `error: 0 / warning: 0`。
    → 教训：**布局权重不要凭感觉，要读量出来的数。**

13. **收尾**：写本文档、更新 `README.md` 索引与命令、发布到桌面。

## 5. 解题内容（与图解析一致，已逐步复核）

### 5.1 真题 1 · 正方体截面

**题干**：正方体 `ABCD-A₁B₁C₁D₁` 体积为 1，`M` 在线段 `BC` 上（异于 `B,C`），
`N` 在线段 `CC₁` 上且 `CN=1/3`。若平面 `AMN` 截正方体所得截面为四边形，求 `BM` 范围。

**推导链**：

```
体积 1 ⇒ 棱长 a = 1
面 ADD₁A₁ ∥ 面 BCC₁B₁（相对面）
  平面 AMN 与前者交于 AD₁，与后者交于 MN  ⇒  AD₁ ∥ MN
  又 AD₁ ∥ BC₁（都是面对角线）           ⇒  MN ∥ BC₁
在 △BCC₁ 中 MN ∥ BC₁  ⇒  CM/CB = CN/CC₁ = 1/3  ⇒  CM = 1/3
临界：BM = 1 − CM = 2/3（此时截面恰过多出的顶点 D₁）
  0 < BM ≤ 2/3 → 截面为四边形 A-M-N-D₁
  BM > 2/3     → 平面又与侧面 ABB₁A₁ 相交，截面变五边形
答案：(0, 2/3]  故选 D
```

### 5.2 真题 2 · 四棱锥

**题干**：四棱锥 `P-ABCD`，`△PBC` 等边，底面 `ABCD` 矩形，平面 `PBC ⊥` 平面 `ABCD`。
`O`、`E` 分别是 `BC`、`PA` 中点，`F` 在线段 `PB` 上（不含端点）。
(1) 若 `PF = 2/3·PB`，证 `O,D,E,F` 四点共面；
(2) 若 `BC = 2AB = 2`，是否存在 `F` 使 `EF` 与平面 `PCD` 所成角正弦值为 `√39/13`？求 `PF/BF`。

**建系**：`BC=2, AB=1`，`△PBC` 等边 ⇒ `PO = √3`。
`PO⊥BC` 且面 `PBC⊥` 面 `ABCD` ⇒ `PO⊥` 底面。取 `AD` 中点 `Q` ⇒ `OQ⊥OC`。
以 `O` 为原点、`OQ` 为 x 轴、`OC` 为 y 轴、`OP` 为 z 轴建系：

```
O(0,0,0)  B(0,−1,0)  C(0,1,0)  A(1,−1,0)  D(1,1,0)  P(0,0,√3)
E = PA 中点 = (1/2, −1/2, √3/2)
F = P + k·(B−P) = (0, −k, √3(1−k))        设 k = PF/PB ∈ (0,1)
```

**(1) 共面** —— 图解析给出两条路，本课件都讲：

```
法一（向量）：PF = 2/3·PB = 2/3·(PO + OB)
            = 2/3·PO + 1/3·DA              ∵ OB = 1/2·DA（DA∥BC 且 DA=BC=2OB）
            = 2/3·PO + 2/3·PE − 1/3·PD     ∵ E 是 PA 中点
   系数和 = 2/3 + 2/3 − 1/3 = 1           ⇒ O,D,E,F 四点共面
   等价短写：OF = 2/3·OE − 1/3·OD
法二（几何）：过 P 作 l∥AD，延长 DE 交 l 于 G
   AD∥BC 且 AD = 2OB，AD = 2PG            ⇒ PG = OB
   △PF′G ∽ △BF′O，PF′/BF′ = PG/OB = 2     ⇒ PF′ = 2/3·PB = PF ⇒ F′=F
   F 在直线 OG 上，O、G 均在平面 ODE 内    ⇒ 四点共面
```

**(2) 存在性**：

```
CD = (1,0,0),  CP = (0,−1,√3)
n·CD = 0 ⇒ x = 0 ;  n·CP = 0 ⇒ y = √3·z ;  取 z = 1
⇒ n = (0, √3, 1),  |n| = 2

EF = PF − PE = k·PB − 1/2·PA = (−1/2, 1/2 − k, √3/2 − √3·k)
|EF| = √(4k² − 4k + 5/4)

sinθ = |EF·n| / (|EF|·|n|) = |√3 − 2√3·k| / (2√(4k² − 4k + 5/4)) = √39/13
⇒ 化简得 9k² − 9k + 2 = 0  ⇒  k = 1/3 或 k = 2/3
两者都满足 0 < k < 1

PF/BF = k/(1−k)  ⇒  k=1/3 时得 1/2；k=2/3 时得 2
答案：存在，PF/BF = 1/2 或 2
```

## 6. 关键技术实现

### 6.1 为什么不用 mathV2 的隐式曲线引擎

`packages/math` 的 `plotImplicit`（marching squares）是为**圆锥曲线** `F(x,y)=0` 设计的。
立体几何的图形是**多面体**，不是隐式曲线，套用不上。

因此本课件只复用**外壳与动效层**（Bento 单文件壳 + SMIL + 控制条），
3D→2D 用生成器内手写的线性投影，与真题精讲里 `prob4Fig`/`prob5Fig` 的做法一致。

### 6.2 正方体：教材斜二测投影

```
screenX = ox + (x + 0.5·y)·s
screenY = oy − (z + 0.5·y)·s        s = 150
```

**血泪教训**：第一版用的是「x 向右下、y 向左上」的轴测（`C30/C45/S30/S45` 那套常数），
结果 `A₁` 投影落在 `ABCD` 四边形**内部**，正方体被压成扁平菱形，完全不像立方体。
斜二测把前面 `ABB₁A₁` 画成正方形、深度方向向右上偏移 45°，上底面才「盖在」下底面之上。

实测顶点坐标（已验证）：

```
A(180,360)  B(330,360)  C(405,285)  D(255,285)
A₁(180,210) B₁(330,210) C₁(405,135) D₁(255,135)
```

被遮挡棱（交于最远顶点 `C` 的三条）画虚线：`BC`、`CD`、`CC₁`。

### 6.3 截面多边形：自动求交，不手写

不硬编码四边形/五边形的顶点，而是用**平面 × 立方体 12 条棱**求交：

```
对每条棱 (P,Q)：f(P)、f(Q) 为平面方程值
  f(P)=0        → P 在平面上，取 P
  f(Q)=0        → 取 Q
  f(P)·f(Q)<0   → 线性插值 t = f(P)/(f(P)−f(Q)) 取交点
去重 → 按「绕质心的极角」排序 → 投影为屏幕坐标 → path
```

好处：`M` 取任意 `t`（0.12 / 0.85 / 2⁄3）都自动得到正确的四边形或五边形，
`BM>2/3` 时五边形多出的那个顶点是算出来的，不是画上去的。

### 6.4 四棱锥：屏幕映射与深度

```
screenX = ox + (x·(−0.45) + y·1 + z·0)·s
screenY = oy + (x·(−0.89) + y·0 + z·(−1))·s     s = 108
```

即：y 轴水平向右、x 轴向左上（远的深度）、z 轴正上。
底面 `AD` 是唯一被遮挡的棱 → 虚线。

### 6.6 内容安全自检（新增，防止整段文字被吞）

Bento 的文本元素按 HTML 解析。**裸露的 `<` 后紧跟字母会被当成标签开头**，
把后面的文字整段吃掉。真题精讲文档 §4 已记录过这个坑（当时 `0<m<1` 未转义导致文字消失）。

本次又踩了一次：第(2)问写 `$0<k<1$`，渲染出来变成乱码 `\dfrac{PF}{BF}=...`。

为此在生成器里加了 `assertContentSafe(doc)`，**生成前扫描所有 text 元素**，
命中即抛错并打印 `slide / element` 定位：

```js
// 对齐 HTML5 词法规则：只有 `<` 后紧跟 字母 / `/` / `!` / `?` 才开启标签
const re = /<[A-Za-z/!?][^>]{0,80}/g;
const SAFE_TAG = /^<\/?(?:b|i|br|em|strong|u|s|sub|sup|span|a)(?:\s[^>]*)?>$/;
```

注意 `re` 刻意**不匹配** `<1`（后跟数字）与 `< BM`（后跟空格）——
这两种在 HTML5 里是安全字面量，实测渲染正常，若一并报错会造成大量误报。
