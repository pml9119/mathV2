## 2. 数学复核（全部结论在代码里由坐标算出或逐式验算）

| 结论 | 验算 |
| --- | --- |
| S3 判定 | 圆 $x^2+y^2=4$ 与 $3x+4y-5=0$：$d=5/5=1<2=r$ ⇒ 相交 |
| S5/S11 弦长 | $d=\lvert1\rvert/\sqrt2=\sqrt2/2$ ⇒ $\lvert AB\rvert=2\sqrt{4-\tfrac12}=\sqrt{14}$ |
| S11 代数法复核 | $2x^2+2x-3=0$，$\Delta=28$ ⇒ $\lvert AB\rvert=\sqrt2\cdot\frac{\sqrt{28}}{2}=\sqrt{14}$ ✔ 两法一致 |
| S6 最短弦 | 圆 $x^2+y^2=25$、$P(3,1)$：$\lvert CP\rvert=\sqrt{10}$ ⇒ 最短 $=2\sqrt{25-10}=2\sqrt{15}$，最长 $=2r=10$ |
| S7 切线 | $x^2+y^2=4$ 上 $P(1,\sqrt3)$：切线 $x+\sqrt3y-4=0$，$d=\frac{\lvert-4\rvert}{2}=2=r$ ✔ |
| S8 两切线 | $P(4,0)$：$\lvert PT\rvert=\sqrt{16-4}=2\sqrt3$；切点 $T_{1,2}(1,\pm\sqrt3)$；切点弦 $4x=4\Rightarrow x=1$；$\angle APB=60^\circ$；四边形面积 $4\sqrt3$ |
| S9 距离最值 | 圆 $x^2+y^2=4$ 到 $3x+4y-25=0$：$d=5$，$r=2$ ⇒ 范围 $[3,7]$ |
| S10 定点 | $(2m+1)x+(m+1)y=7m+4\Rightarrow m(2x+y-7)+(x+y-4)=0$ ⇒ $P(3,1)$；$\lvert PC\rvert=\sqrt5<5=r$ ⇒ 在圆内 ⇒ 恒相交 |
| S12 真题 | $d=\frac{r^2}{\sqrt{a^2+b^2}}$：A ✔（$=r$ 相切）、B ✔（$<r\Rightarrow d>r$ 相离）、C ✘（应为相交）、**答案 ABD** |

图上的关键点**不是画上去的，是算出来的**：
S2/S5 的弦端点用勾股求半弦，S6/S10 的弦端点用「直线 × 圆」求交，
S8/S11 的切点、交点由坐标变换得到。

## 3. 图形与动画的实现要点

### 3.1 世界坐标 → 屏幕坐标，一次线性变换

```js
view(s, ox, oy) → P(x, y) = [ox + x*s, oy - y*s]   // 数学 y 向上，SVG y 向下
```

题目里的坐标（$P(3,1)$、$T_1(1,\sqrt3)$、$C(1,2)$…）**直接喂进 `P()`**，
图与算式共用同一套数字，避免「图画一套、算式写一套」。

### 3.2 动画只用三种 SMIL，全部采样成 values 值表

- `<line>` 动 `x1,y1,x2,y2`（`animLine`）
- `<circle>` 动 `cx,cy`（`animDot`）
- `<text>` 动 `x,y`（`animText`，本课新增：动点标签跟着点走）

**直角标记画成两段 `<line>`，不去动 `path` 的 `d`** —— 少一个不确定因素。
所有采样共享同一个 `dur`，所以点、线、标记永远同步；控制条拖动时整体一起走。

### 3.3 图注必须让开右下角的控制条

智能控制条的浮条钉在**右下角**（实测其左缘 ≈ viewBox `x=288`）。
`build-solid.mjs` 的图注居中放在底部，实测**被控制条压掉半句**。
本课的处理：图注统一左下角，并且 `cap()` **按估算宽度自动缩字号**
（`CAP_SAFE = 262`），从代码上保证它压不到控制条——不靠人记得"别写太长"。

## 4. 布局：卡片高度按内容分配

`stepCards()` 不手填高度，而是：

```
need_i = 上边距 12 + 标题行 25 + 间隙 6 + 正文估算高度 + 下边距 10
h_i    = 整列可用高度 × need_i / Σneed          // 内容多的卡自然拿到更多高度
```

- 正文用 `autoH`（盒高跟内容算），**不手填**（红线 6：手填值必然与内容失配）。
- Σneed 超过列高时生成器**显式告警**，提示回改文案，而不是悄悄压扁卡片。
- 最终把关仍是 `validate`（浏览器实测）——估算器只负责"随内容同步变化"。

### 4.1 估算器的一处实测校准（本课最重要的一条经验）

首轮 `validate` 报 **7 处文字溢出，全部是「少算一整行」**。根因不是行高，而是**宽度**：
按源码字符数估宽时，**含行内公式的段落会系统性偏窄** ——
`\dfrac{}{}`、`\sqrt{}`、上下标在 KaTeX 里占的横向宽度，明显大于它在源码里看起来的长度。

修法：把 `&lt;/&gt;/&nbsp;` 先还原成 1 个字符，再对含 `$` 的段落按渲染宽度放量。
（`build-deck.mjs` 里的同名函数没有这一步，是它当年留下 21 处溢出的同一类原因。）

## 5. 过程中踩到并修掉的三个坑

1. **图注被控制条压住**（S5）：见 §3.3。修法是机械的：宽度超限自动缩字号。
2. **溢出估算少算一行**（7 处）：见 §4.1。
3. **用 PowerShell 整文件重写源码，把中文编码写坏了**：
   `Get-Content -Raw` 以非 UTF-8 解码后再写回，全文件中文变成「UTF-8 被当 GBK 读」的乱码，
   且**不可逆**（710 处字符已丢失），只能整份重建。
   → 教训：**源码只用 edit/write 工具改**；确需脚本时也要用 `[IO.File]::WriteAllBytes`
   且**绝不经过字符串解码**。（与契约 §5.1 同源，但这次是编码而不是 `$'`。）
